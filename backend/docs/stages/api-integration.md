| # | Method & Path                               | Front-end view / moment that calls it                                                                                                                                        | Payload in (DTO)                                                                                                          | Payload out (DTO)                                                                                                  | What it does                                                                                                       |
| - | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 1 | **POST  /api/v1/auth/register**             | **Sign-up page**<br>When the candidate presses **“Create account.”**                                                                                                         | `UserRequestDTO`<br>↳ `fullName`, `email`, `password`                                                                     | `UserResponseDTO`<br>↳ `id`, `fullName`, `email`, *createdAt*                                                      | Creates a new user row and logs them in (token or session cookie is set by the `UserService`).                     |
| 2 | **POST  /api/v1/auth/login**                | **Login modal / page**                                                                                                                                                       | `AuthenticationDTO`<br>↳ `email`, `password`                                                                              | `UserResponseDTO` (+ JWT / cookie)                                                                                 | Authenticates and returns the candidate profile.                                                                   |
| 3 | **POST  /api/v1/sessions**                  | **Interview lobby** – after the user selects tech-stack, difficulty, company tier, etc.                                                                                      | `InterviewSessionRequestDTO`<br>↳ `candidateId`, `preferences` (`TechStack`,`ExperienceLevel`,`Difficulty`,`CompanyTier`) | `InterviewSessionResponseDTO`<br>↳ `sessionId`, `startedAt`, `preferences`, `active=true`, `currentPhase=BASELINE` | Creates a brand-new interview session and initialises Phase 1.                                                     |
| 4 | **GET  /api/v1/sessions/{id}**              | **Resume interview** (page refresh or returning candidate)                                                                                                                   | –                                                                                                                         | `InterviewSessionResponseDTO`                                                                                      | Fetches full session state, including phases & timestamps.                                                         |
| 5 | **POST  /api/v1/sessions/{id}/phases/next** | **IDE / chat split-view** – “Next phase” is triggered automatically by the orchestration engine; the front-end calls this to fetch the very first question of the new phase. | path param `id`                                                                                                           | `PhaseResponseDTO`<br>↳ `phaseType`, `question` (first in phase), timers, metadata                                 | Advances to the next PhaseType (BASELINE → SCENARIO → ARCHITECTURE → DEEP\_DIVE) and returns the opening question. |
| 6 | **POST  /api/v1/sessions/answers**          | **IDE / chat split-view** – when the candidate hits **“Submit answer.”**                                                                                                     | `AnswerRequestDTO`<br>↳ `questionId`, `content` (code / text)                                                             | `AnswerResponseDTO`<br>↳ `answerId`, `questionId`, `submittedAt`                                                   | Persists the answer, kicks off scoring & phase-progress checks.                                                    |
| 7 | **POST  /api/v1/sessions/answers/score**    | *Admin / proctor tool* or a retry flow (optional)                                                                                                                            | `AnswerScoreRequestDTO`<br>↳ `answerId`                                                                                   | `AnswerScoreResponseDTO`<br>↳ `score`, `rubricFeedback`                                                            | Re-scores an answer or attaches manual override feedback.                                                          |
| 8 | **POST  /api/v1/sessions/run**              | **IDE panel** – “Run code” (quick compile/run, *doesn’t* save)                                                                                                               | `RunRequestDTO`<br>↳ `language`, `sourceCode`, `stdin`                                                                    | `RunResultDTO`<br>↳ `stdout`, `stderr`, `timeMs`, `memoryKb`, `exitCode`                                           | Sends code to Judge0 (or whichever runner) and streams the execution result back.                                  |
